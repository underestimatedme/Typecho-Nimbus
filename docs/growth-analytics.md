# 来源与作品点击统计（NimbusKit 1.2）

## 启用与目标

同时更新 Nimbus 主题和 NimbusKit 插件。插件设置中开启「来源与作品点击统计」并保存；保存时为旧库创建 `nimbus_growth` 表，无需停用插件。默认关闭；关闭后不发采集请求。后台「管理 → Nimbus → 统计」显示近 14 天汇总，旧版主题不会发送事件，旧版插件不会暴露该功能。

每行 `英文标识|显示名称|公开URL`，最多 20 个，例如：

```text
source|查看源码|https://github.com/example/project
intro|产品介绍|/product.html
```

目标仅标记现有链接，不会自动生成按钮。标识以小写字母开头，最长 40 字符；支持数字、下划线、短横线。无效行忽略，重复标识首行生效。只配置公开链接，不放令牌、后台入口或私人信息。目标会进入前台配置。重复指向同一路径只匹配首个目标。

链接匹配忽略查询参数、锚点和末尾斜线，按目标 URL 的域名和路径匹配；不能区分同一路径的不同查询操作。点击统计是链接被点击，不代表目标加载成功、注册或购买。

## 来源与口径

传播链接可加 `?utm_source=juejin`，已有查询参数用 `&utm_source=juejin`。来源优先使用 UTM，其次使用浏览器提供的来源主机名。支持 juejin、wechat（weixin）、xiaohongshu（xhs）、github、v2ex、google、bing、baidu；未知值归为 other，不保留原始值。来源缺失或站内来源归为「直接 / 来源不可知」。平台应用可能隐藏来源，因此缺失不等于自然流量。

首次事件的来源用第一方 HttpOnly / SameSite=Lax Cookie 保留 30 分钟；同浏览器到访和每个目标点击在各自 30 分钟窗口内去重。内部路由切换保留来源，并替换事件监听器。只计算开启之后的访问，不回填旧传播数据。按站点时区保存日期，数据表只有日期、事件类型、来源分类、目标标识和计数。

不保存 IP、UA、完整来源 URL、页面查询参数或访客身份。DNT/GPC 访问与已登录 Typecho 用户不计入；测试时需使用匿名浏览器。普通评论或 GitHub 评论身份不属于 Typecho 后台登录。关闭 Cookie、禁用 JavaScript、广告拦截、网络失败及并发首请求会影响计数。Cookie 可被删除或伪造，因此是近似的浏览器事件数，不是 UV、审计数据或销量。后端限制同站 POST 和配置目标，但没有反作弊或跨设备身份追踪。

## 上线核验

1. 更新两份代码，保持默认关闭，确认页面正常。
2. 填真实公开目标，开启并保存；打开后台统计确认无建表提示。
3. 匿名打开带 UTM 的传播链接，点击一个配置目标；后台应新增对应来源和点击。30 分钟内刷新、重复点击应不累加。
4. 在已登录后台的浏览器重复操作，应不增加。隐私偏好开启时也不采集。
5. 将人工检查时间写入传播记录，避免当成自然读者；来源未知与未采集字段留空或标注未知。

本地验证使用独立数据库。SQLite 运行集成测试；MySQL / PostgreSQL 的建表语法经过单元测试，未连接实际服务器验证。禁用插件默认保留数据；选择删除全部数据再停用会连同这张表一起删除。
